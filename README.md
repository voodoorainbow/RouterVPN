# RouterVPN

Мониторинг и автоматический failover WireGuard на роутерах **Keenetic** (Entware).

Проект следит за активностью WireGuard-туннелей и, если туннель, через который идут IPv4-маршруты, перестаёт отвечать, переключает маршруты, политику подключений и DNS на другой активный туннель.

## Зачем это нужно

На Keenetic часто настраивают несколько WireGuard-подключений и большой список статических маршрутов (или политику VPN) через один из них. Если этот туннель падает, трафик «залипает», пока маршруты вручную не перенесут на другой интерфейс.

**RouterVPN** делает это автоматически и показывает статус в веб-дашборде.

## Возможности

- Веб-дашборд со всеми WireGuard-интерфейсами: online / handshake / трафик / endpoint
- Определение интерфейса, на который сейчас смотрят статические IPv4-маршруты
- Проверка по расписанию (по умолчанию каждые 5 минут; интервал меняется в веб-UI)
- Автоfailover на активный туннель (порядок предпочтения задаётся в конфиге)
- Ручное переключение из UI
- Backup списка маршрутов перед массовой сменой
- Низкая нагрузка в штатном режиме (короткий пик при проверке, тяжёлая работа только при реальном failover)

## Состав репозитория

```text
wg-monitor/                 # приложение для Entware
  main.py                   # точка входа (демон + HTTP UI)
  lib/                      # RCI-клиент, монитор, failover, веб
  config.example.json       # пример конфигурации
  install.sh                # установка в /opt
  entware/S99wg-monitor     # автозапуск
  scripts/deploy.sh         # выкладка по SSH (порт Entware, обычно 222)
  scripts/run-lan.sh        # запуск с ПК в LAN (без установки на роутер)
  README.md                 # подробная установка и эксплуатация
```

## Требования

- Роутер Keenetic с компонентом **OPKG**
- Установленный **Entware** (раздел в ext2/ext3/ext4 или внутренняя память `storage:/`)
- Python 3 в Entware (`python3-light` достаточно для базового набора)
- Учётная запись Keenetic с доступом к веб/RCI

## Быстрый старт

1. Скопируйте пример конфига и укажите логин/пароль администратора роутера:

```bash
cd wg-monitor
cp config.example.json config.json
# отредактируйте username / password / rci_url
```

2. Установите на Entware (пример для SSH Entware на порту 222):

```bash
chmod +x scripts/deploy.sh install.sh
./scripts/deploy.sh root@192.168.1.1 222
```

Либо распакуйте проект на роутере и выполните:

```bash
/opt/bin/sh ./install.sh
```

3. Откройте дашборд:

```text
http://<IP-роутера>:8088/
```

Подробности: [wg-monitor/README.md](wg-monitor/README.md).

## Как работает failover

1. Через Keenetic RCI читается состояние всех интерфейсов `Wireguard*`.
2. Туннель считается активным, если peer online и свежий handshake.
3. Определяется WG-интерфейс, на который указывает большинство статических маршрутов.
4. Если он неактивен и autofailover включён — выбирается другой активный туннель (по `preference` или любой online).
5. Батчами переписывается `interface` у статических маршрутов, обновляются политика VPN и DNS, конфигурация сохраняется.

> На роутере с тысячами статических маршрутов failover может занять от десятков секунд до нескольких минут и заметно загрузить CPU. В обычном режиме мониторинга нагрузка почти нулевая.

## Безопасность

- Не коммитьте `config.json` и файлы с паролями — в `.gitignore` это уже учтено.
- Дашборд по умолчанию без отдельной авторизации: используйте только в доверенной LAN (или закройте порт файрволом / VPN).
- RCI-учётные данные храните в `/opt/etc/wg-monitor/config.json` с правами `600`.

## Совместимость

Разрабатывалось и проверялось на KeeneticOS 5.x (в т.ч. модели линейки KN). API — официальный RCI веб-интерфейса Keenetic.

## Лицензия

Код в репозитории предоставляется «как есть», без гарантий. Используйте на свой риск: автоматическая смена маршрутов влияет на доступность сети.
